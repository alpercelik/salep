### How to Modify This Code

To alter the generated types or client behaviors, always modify upstream sources:

1. **Schema & Types**: Edit the GraphQL SDL schema file (e.g. `schema.graphql`).
2. **Operations & Queries**: Edit or add `.graphql` files in the configured operations directory.
3. **Configuration**: Edit `salep.json` (for namespaces, client name, scalar mappings, NodaTime, transport options).
4. **Regenerate**: Run `dotnet build` (or execute `dotnet run --project .../Salep.ClientGenerator.Cli.csproj -- --config salep.json`).

### Consumption Rules for AI Agents

When consuming or referencing this generated client in application code, adhere to these invariants:

1. **Read-Only API Discovery**:
   - Treat generated files as a strongly-typed, read-only contract.
   - Inspect the generated client class and operation models to discover available methods, parameter inputs, and response payloads.
   - Specific operation contracts and models are self-documenting in the generated C# code.

2. **Discriminated Unions (C# 15)**:
   - GraphQL unions and interfaces are emitted as native C# 15 union declarations.
   - Use exhaustive type-pattern `switch` expressions to handle each case.

3. **Dependency Injection**:
   - Register the generated client with `IHttpClientFactory` in `Program.cs` / `IServiceCollection`:
     ```csharp
     builder.Services.AddHttpClient("graphql");
     builder.Services.AddTransient(provider => new GraphQLClient(
         provider.GetRequiredService<IHttpClientFactory>().CreateClient("graphql"),
         new Uri("https://api.example.com/graphql")));
     ```

4. **GraphQL Error Handling**:
   - Always check `response.Errors` before accessing `response.Data`.
   - GraphQL allows partial responses where `Data` may be partially populated alongside error messages.

5. **Multi-Project Deduplication**:
   - In solutions utilizing explicit client references (`"baseClient"` in a version 1 client configuration), symbol ownership is tracked in `.salep.manifest.json`.
   - Build referenced client projects first; missing or stale contracts are errors. Profiles share defaults and never establish symbol ownership.
   - Types defined and generated by ancestor projects are automatically suppressed in downstream modules to prevent duplicate C# symbol definitions (`CS0433`).
